# Reefer check: застосунок для телефону

Офлайн-застосунок (PWA) для електро команди. План погрузки готують у книзі Excel «Reefer spot plan» (.xlsm) на робочому ПК. Далі план переходить на телефони, і рефи відмічають там, а не на роздрукованих бей-планах. Наприкінці відмітки та журнал повертаються в Excel.

Застосунок: **https://mad-doc-ua.github.io/reefer-check/**. Відкрийте посилання один раз за наявності інтернету й додайте на головний екран («Install app» / «Add to Home Screen»). Після цього він працює без мережі.
Якщо це посилання не відкривається (у деяких мережах / на деяких телефонах), використовуйте запасне: **https://reefer-check.pages.dev/** (той самий застосунок, інший хостинг).
На iPhone посилання з WhatsApp / Telegram треба спершу відкрити в Safari (іконка компаса), потім Share → Add to Home Screen.
Тільки застосунок з іконки працює на весь екран і має власне сховище (план, відкритий у вкладці Safari, туди не переходить); у браузері на iPhone застосунок показує цю інструкцію.

Інтерфейс англійською, бо екіпаж багатонаціональний. Повний опис книги Excel зберігається окремо, поза репозиторієм.

## Як це працює

```
ПК (Excel, EXPORT TO PHONE .xlsx) ──Bluetooth або reefer-sender.html (QR)──▶ Android
Android ──QR──▶ iPhone / інший телефон
Телефони ──CSV / QR──▶ ПК ──IMPORT PHONE LOG──▶ Excel
```

1. В Excel імпортують BAPLIE (план приходу й план погрузки) та маніфести і натискають **EXPORT TO PHONE**
   (з книги v26). Поруч із книгою з'являється маленький файл `Reefer phone <порт> <дата>.xlsx`: лише значення, без макросів, обидва плани.
2. План потрапляє на телефон одним із двох способів:
   - файл `.xlsx` (або збережена книга `.xlsm`) по Bluetooth, далі **Open plan** на телефоні. На Android отриманий файл можна
     відкрити й одразу: **Поділитися → Reefers** (застосунок встановлений на головний екран);
   - сторінка `reefer-sender.html` на ПК, яка показує план циклом QR-кодів.
3. На палубі й у трюмах телефон відмічає рефи. Мережа для цього не потрібна.
4. Телефони обмінюються планом і відмітками через QR.
5. Відмітки й журнал повертаються на ПК одним файлом, log CSV (**Send log to PC**: меню «Поділитися», Bluetooth), і в Excel імпортуються кнопкою **IMPORT PHONE LOG**.
6. Наприкінці порту в Excel натискають **CLOSE PORT**, а на телефонах порт закривається, коли відкривають план наступного порту.

## Що вміє

### План і бей-план
- Відкриває файл EXPORT TO PHONE (`.xlsx`) або збережену книгу `.xlsm`. Читає аркуші LOADING (фінальний план), DISCHARGE (план приходу, з книги v24),
  Special, ATTENTION, Notes, Home, PortGroups та positions.
- Список беїв (02.03 … 66) показує прогрес, тобто скільки рефів уже відмічено. Перемикач **Tiles / Overview**: Overview показує всі беї
  на одній сторінці, як аркуш Overview у книзі (слоти з розетками, рефи кольором категорії, прогрес під кожним беєм, таблиця PORT / POL / POD і легенда).
  Бей не вужчий за ~160 px: на телефоні 2 в рядку, на планшеті більше.
- У LOAD і DISCH на бей-плані та Overview намальовані тільки рефи цієї роботи в порту, інші слоти порожні. Увесь судновий план видно в ALL.
- Бей-план має DECK і HOLD, ряди 14…01…13. Кольори такі самі, як на Overview: R означає restow, T означає різницю температур.
- 20' слоти поділені навпіл: зверху fore, знизу aft. Одиночний 20' займає весь слот і підписаний 20A або 20F.
- Пошук працює за номером (від 3 символів) або за позицією.

### Режими
- **LOAD at порт**: показує рефи з POL = порт плюс усі restow (на фінальній позиції), дія Connected. Restow, вивантажений у DISCH, тут має кнопку Reconnect (restow loaded back).
- **DISCH at порт**: показує рефи з POD = порт плюс усі restow, дії Disconnected, потім Discharged. Вивантажені стають сірими. Restow-контейнер після вивантаження можна знову підключити (Reconnect), і він теж іде в прогрес як готовий.
  Restow визначається за номером контейнера: колонка RESTOW у LOADING, або реф є і в плані прибуття, і у фінальному плані, але стоїть на іншій позиції (moved) чи планер дав йому POL = цей порт. У DISCH такий реф намальований на позиції прибуття, у LOAD та ALL на фінальній. Restow стосується лише поточного порту плану (CURRENT PORT): якщо вибрати інший порт, це звичайний реф.
- **ALL**: показує весь план.
- **Quick mark**: один дотик по слоту робить наступний крок для поточного режиму. Скасувати крок можна через картку контейнера.

### Картка контейнера
- Статус, а також «знайдено в іншому місці»: бей, за бажанням і точна позиція tier/row/40'/20'.
- Теги (problem, out of range, alarm, no power, damaged) і нотатка.
- Історія дій із цим контейнером.

### Нагадування
- Якщо реф відключений довше заданого часу (1/2/3/4 год, за замовчуванням 2) і вивантаження ще не підтверджене, з'являються червоний банер, блимаюча клітинка й рядок на вкладці Issues.
- Системне сповіщення телефона спрацьовує лише в межах того, що дозволяє браузер.

### Новий план поверх старого
- Відмітки прив'язані до номера контейнера, а не до позиції.
- Переставлений контейнер потрапляє в Issues з проханням перевірити ще раз.
- Відмічений контейнер, якого немає в новому плані, потрапляє в «Marked but not in the new plan».
- Якщо контейнер раніше «знайшли в бей X» і новий план з цим погодився, проблема закривається сама.
- **Список на вивантаження.** Рефи з плану приходу (DISCHARGE), яких немає в плані погрузки (LOADING), показуються в режимі DISCH на позиціях приходу.
  Тому і новий телефон колеги одразу бачить, що вивантажувати. Якщо позиція в плані погрузки інша, ніж на приході, картка показує позицію приходу.
  Для старих файлів без DISCHARGE (книга до v24) список, як і раніше, береться з попереднього плану на телефоні. На вкладці Plan список можна закрити.
- Вивантажені контейнери, яких немає в новому плані, зникають без попереджень.

### Закриття порту
- Коли відкривається план (файлом або через QR) для іншого CURRENT PORT, телефон питає, чи закрити попередній порт.
  Те саме можна зробити кнопкою **Close port** на вкладці Plan, у два кроки: 1. **Send log to PC**, 2. **Close port**.
- Під час закриття відмітки й журнал порту переходять в архів на телефоні (останні 3 порти). Звідти їх можна надіслати: **Log to PC** або файл відміток для телефонів.
  Робочий журнал очищується. Рефи, що лишаються на борту, переходять у новий порт зі статусом (підключений / відключений),
  «знайдено в іншому місці», тегами й нотатками. Вивантажені починають з чистого.
- Якщо лог закритого порту ще не надіслано з кроку 1, угорі вкладки Plan висить картка **For the PC: log of <порт>**, доки лог не надіслано
  або не натиснуто «Done, it is on the PC».
- Після закриття відмітки й рядки журналу, старші за час закриття, при злитті (QR або файл колеги) ігноруються.
  Так само діє час CLOSE PORT з Excel (PhoneCutoff, який передається у файлі). Тому дані закритого порту не змішуються з новим і не повертаються в Excel.

### Журнал
- При першому запуску телефон питає ім'я. Кожна відмітка, тег, нотатка й новий план записуються з часом та ім'ям.
- Журнал видно в картці контейнера (History) і на вкладці Plan.
- Це не акаунт: ім'я зберігається тільки на телефоні.

### Обмін даними
- **Телефон → телефон через QR** (вкладка Plan). Один телефон показує цикл QR-кодів з планом і відмітками (за бажанням і з журналом), інший зчитує їх камерою в будь-якому порядку. Пропущені коди підхоплюються на наступному колі. Перед застосуванням показується підсумок. План на 262 рефи займає близько 22 кодів, тобто приблизно 8 с на цикл. Працює без мережі й на айфонах.
- **Файл відміток** (розділ «For a colleague's phone»). **Send marks file** відкриває меню «Поділитися» (месенджер, Bluetooth, AirDrop),
  **Merge marks file** зливає файл колеги (виграє новіша зміна; вибрати можна будь-який файл, застосунок сам перевіряє вміст). Журнали при цьому теж об'єднуються.
  Після злиття видно, скільки рефів оновлено, скільки вже були актуальні і скільки пропущено як дані закритого порту.
- QR і файл відміток передають лише відкритий порт: те, що позначено до останнього закриття порту (на телефоні або CLOSE PORT в Excel), колегам не йде.
- **CSV для Excel** (розділ «For the PC (Excel)»: **Send log to PC**). Журнал іде як CSV з часом у форматі `yyyy-mm-dd hh:mm:ss`, який Excel розуміє незалежно від мови системи.

### Дані
- Усе зберігається тільки на телефоні (localStorage) і нікуди не надсилається. Сервера немає.
- Картка **Storage on this phone** показує зайняте місце і чи захищені дані від автоматичного видалення браузером. Найкраще встановити застосунок на головний екран.
  На iPhone застосунок з головного екрана показує "home-screen app": iPhone не чистить його дані через невикористання (вкладку Safari може очистити приблизно через 7 днів).
- Якщо збереження не вдалося або місце заповнене понад 80 %, угорі з'являється червона плашка.
- **Заставка**: завжди темна, галочка на лого пульсує, поки застосунок відкривається. Іконки й заставку робить `app/scripts/make-icons.py`
  з `design/logo-watercolor.jpg` (`python scripts/make-icons.py ../design/logo-watercolor.jpg --glow 1300,872`).
- **Reset this phone**: кнопку треба утримувати 3 с. Стирає план, відмітки, теги, нотатки, журнал і архів портів; ім'я й нагадування лишаються. Перед цим можна зберегти резервний файл (його відмітки й журнал повертає "Merge marks file").

## Сторінка для ПК: `reefer-sender.html`

Один самодостатній HTML-файл. Він відкривається в браузері на ПК без інсталяції та без інтернету.
- **Книга → телефони.** Виберіть файл EXPORT TO PHONE (`.xlsx`) або `.xlsm`. Сторінка покаже, скільки рефів у фінальному плані й скільки тільки в плані приходу, і цикл QR-кодів, які телефони зчитують на вкладці Plan.
- **Телефони → Excel.** Відмітки з телефонів зчитуються вебкамерою з QR або завантажуються файлом `.json`. Сторінка зберігає два CSV: marks (з колонкою UPDATED, тож в Excel виграє новіша зміна) і log.

Збирання: `npm run build:sender`. Результат буде в `app/dist-sender/reefer-sender.html`.

## Імпорт у Excel (з версії книги v23)

Макрос **IMPORT PHONE LOG** є на Home, на LOADING і на PHONE MARKS. Він приймає CSV з телефона або зі сторінки для ПК, кілька файлів одночасно, і заповнює:
- **PHONE LOG**: дії з контейнерами, найновіші зверху. Рядок, який уже є, вдруге не додається.
- **PHONE MARKS**: один рядок на контейнер з останнім статусом.
- **LOADING AR:AU**: статус, час, хто відмітив і нотатка з телефона.
- **Бей-плани**: C (connected) або D (discharged) у клітинці між POL і POD.

## Розробка (на ноутбуці)
```
cd app
npm install
npm run dev           # http://localhost:5173, тестові дані: http://localhost:5173/?x#demo:p1.xlsx (файли в app/localtest/)
npm run build         # застосунок у app/dist
npm run build:sender  # сторінка для ПК у app/dist-sender
```
Кожен push у `main` автоматично публікує застосунок на GitHub Pages (`.github/workflows/pages.yml`).

Файли `.xlsm`, `.BAP`, маніфести, CSV та папки `testdata/`, `app/localtest/` не потрапляють у git, бо в них дані вантажу.
