# Reefer check: застосунок для телефону

Офлайн-застосунок (PWA) для електро команди. Ви готуєте план погрузки у книзі Excel «Reefer spot plan» (.xlsm) на робочому ПК, передаєте файл на телефон і відмічаєте рефи на телефоні, а не на папері.

Повний опис книги Excel зберігається окремо, поза репозиторієм.

## Що вміє (прототип v0.1)
- Відкриває збережений у Excel `.xlsm` (аркуші LOADING, Special, ATTENTION, Notes, Home, PortGroups, positions).
- Список беїв (02.03 ... 66) показує прогрес: скільки рефів відмічено.
- Бей-план: DECK і HOLD, ряди 14…01…13. Кольори як на Overview, R означає restow, T означає різницю температур. 20' слоти поділені навпіл: зверху fore, знизу aft.
- Картка контейнера: «завантажено», «знайдено в іншому місці» (бей, а за бажанням точна позиція tier/row/40'/20'), теги (problem, out of range, alarm, no power, damaged) і нотатка.
- Журнал дій: при першому запуску телефон питає ім'я. Кожна відмітка, тег, нотатка й новий план записуються з часом та ім'ям. Видно в картці контейнера (History), на вкладці Plan, і можна зберегти як CSV для Excel. Під час злиття файлів відміток журнали теж об'єднуються. Це не акаунт: ім'я зберігається тільки на телефоні.
- Режим «Quick mark»: один дотик по слоту відмічає реф.
- Пошук за номером (від 3 символів) або позицією.
- Фільтр портів: All / Loading at / Discharging at.
- **Новий план поверх старого:** відмітки прив'язані до номера контейнера. Якщо контейнер переставили, він потрапляє в Issues з проханням перевірити ще раз. Якщо його прибрали з плану, він потрапляє в «Marked but not in the new plan». Якщо раніше він був «знайдено в бей X» і новий план з цим погодився, проблема закривається сама.
- Відмітки можна зберегти у файл і злити з файлом колеги (виграє новіша зміна).
- Дані зберігаються тільки на телефоні й нікуди не надсилаються.

## Ще не зроблено
- Передача плану й відміток між телефонами через QR-коди (для айфонів).
- Розміщення застосунку на хостингу та встановлення на телефони.
- Кнопка EXPORT TO PHONE в Excel (маленький файл замість цілого .xlsm).

## Розробка (на ноутбуці)
```
cd app
npm install
npm run dev      # http://localhost:5173, тестові дані: http://localhost:5173/?x#demo:v22.xlsm (файли в app/localtest/)
npm run build    # готовий застосунок у app/dist
```
Файли `.xlsm`, `.BAP`, маніфести та папки `testdata/`, `app/localtest/` не потрапляють у git, бо в них дані вантажу.
