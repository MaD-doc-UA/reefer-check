# Reefer check: застосунок для телефону

Офлайн-застосунок (PWA) для електро команди. План погрузки готують у книзі Excel «Reefer spot plan» (.xlsm) на робочому ПК. Далі план переходить на телефони, і рефи відмічають там, а не на роздрукованих бей-планах. Наприкінці відмітки та журнал повертаються в Excel.

Застосунок: **https://mad-doc-ua.github.io/reefer-check/**. Відкрийте посилання один раз за наявності інтернету й додайте на головний екран («Install app» / «Add to Home Screen»). Після цього він працює без мережі.

Інтерфейс англійською, бо екіпаж багатонаціональний. Повний опис книги Excel зберігається окремо, поза репозиторієм.

## Як це працює

```
ПК (Excel .xlsm) ──Bluetooth або reefer-sender.html (QR)──▶ Android
Android ──QR──▶ iPhone / інший телефон
Телефони ──CSV / QR──▶ ПК ──IMPORT PHONE LOG──▶ Excel
```

1. В Excel імпортують BAPLIE та маніфести й зберігають книгу.
2. Книга потрапляє на телефон одним із двох способів:
   - файл `.xlsm` по Bluetooth, далі **Open plan** на телефоні;
   - сторінка `reefer-sender.html` на ПК, яка показує план циклом QR-кодів.
3. На палубі й у трюмах телефон відмічає рефи. Мережа для цього не потрібна.
4. Телефони обмінюються планом і відмітками через QR.
5. Відмітки й журнал повертаються на ПК як CSV і в Excel імпортуються кнопкою **IMPORT PHONE LOG**.

## Що вміє

### План і бей-план
- Відкриває збережений у Excel `.xlsm` і читає аркуші LOADING, Special, ATTENTION, Notes, Home, PortGroups та positions.
- Список беїв (02.03 … 66) показує прогрес, тобто скільки рефів уже відмічено.
- Бей-план має DECK і HOLD, ряди 14…01…13. Кольори такі самі, як на Overview: R означає restow, T означає різницю температур.
- 20' слоти поділені навпіл: зверху fore, знизу aft. Одиночний 20' займає весь слот і підписаний 20A або 20F.
- Пошук працює за номером (від 3 символів) або за позицією.

### Режими
- **LOAD at порт**: показує рефи з POL = порт, дія Connected.
- **DISCH at порт**: показує рефи з POD = порт плюс усі restow, дії Disconnected, потім Discharged. Вивантажені стають сірими. Restow-контейнер після вивантаження можна знову підключити (Reconnect).
- **ALL**: показує весь план.
- **Quick mark**: один дотик по слоту робить наступний крок для поточного режиму. Скасувати крок можна через картку контейнера.

### Картка контейнера
- Статус, а також «знайдено в іншому місці»: бей, за бажанням і точна позиція tier/row/40'/20'.
- Теги (problem, out of range, alarm, no power, damaged) і нотатка.
- Історія дій із цим контейнером.

### Нагадування
- Якщо реф відключений довше заданого часу (1/2/3/4 год, за замовчуванням 2) і вивантаження ще не підтверджене, з'являються червоний банер, блимаюча клітинка й рядок на вкладці Issues.
- Системне сповіщення телефона спрацьовує лише в межах того, що дозволяє браузер.

### Новий план поверх старого
- Відмітки прив'язані до номера контейнера, а не до позиції.
- Переставлений контейнер потрапляє в Issues з проханням перевірити ще раз.
- Відмічений контейнер, якого немає в новому плані, потрапляє в «Marked but not in the new plan».
- Якщо контейнер раніше «знайшли в бей X» і новий план з цим погодився, проблема закривається сама.
- **Список на вивантаження.** Якщо на порту приходить план погрузки, рефи попереднього плану з POD = поточний порт, яких у новому плані немає й які ще не вивантажені, лишаються списком на вивантаження. Їх видно в режимі DISCH на старих позиціях. На вкладці Plan цей список можна закрити.
- Вивантажені контейнери, яких немає в новому плані, зникають без попереджень.

### Журнал
- При першому запуску телефон питає ім'я. Кожна відмітка, тег, нотатка й новий план записуються з часом та ім'ям.
- Журнал видно в картці контейнера (History) і на вкладці Plan.
- Це не акаунт: ім'я зберігається тільки на телефоні.

### Обмін даними
- **Телефон → телефон через QR** (вкладка Plan). Один телефон показує цикл QR-кодів з планом і відмітками (за бажанням і з журналом), інший зчитує їх камерою в будь-якому порядку. Пропущені коди підхоплюються на наступному колі. Перед застосуванням показується підсумок. План на 262 рефи займає близько 22 кодів, тобто приблизно 8 с на цикл. Працює без мережі й на айфонах.
- **Файл відміток.** Відмітки можна зберегти у файл і злити з файлом колеги (виграє новіша зміна). Журнали при цьому теж об'єднуються.
- **CSV для Excel.** Журнал зберігається як CSV з часом у форматі `yyyy-mm-dd hh:mm:ss`, який Excel розуміє незалежно від мови системи.

### Дані
- Усе зберігається тільки на телефоні (localStorage) і нікуди не надсилається. Сервера немає.

## Сторінка для ПК: `reefer-sender.html`

Один самодостатній HTML-файл. Він відкривається в браузері на ПК без інсталяції та без інтернету.
- **Книга → телефони.** Виберіть `.xlsm`, і сторінка покаже цикл QR-кодів, які телефони зчитують на вкладці Plan.
- **Телефони → Excel.** Відмітки з телефонів зчитуються вебкамерою з QR або завантажуються файлом `.json`. Сторінка зберігає два CSV: marks (з колонкою UPDATED, тож в Excel виграє новіша зміна) і log.

Збирання: `npm run build:sender`. Результат буде в `app/dist-sender/reefer-sender.html`.

## Імпорт у Excel (з версії книги v23)

Макрос **IMPORT PHONE LOG** є на Home, на LOADING і на PHONE MARKS. Він приймає CSV з телефона або зі сторінки для ПК, кілька файлів одночасно, і заповнює:
- **PHONE LOG**: дії з контейнерами, найновіші зверху. Рядок, який уже є, вдруге не додається.
- **PHONE MARKS**: один рядок на контейнер з останнім статусом.
- **LOADING AR:AU**: статус, час, хто відмітив і нотатка з телефона.
- **Бей-плани**: C (connected) або D (discharged) у клітинці між POL і POD.

## Ще не зроблено
- Кнопка EXPORT TO PHONE в Excel (маленький файл замість цілого .xlsm).
- Додаткові поля перевірки для special-рефів (pharma / CT / CA).
- Фото до відміток (відкладено: незрозуміло, як переносити їх на ПК).

## Розробка (на ноутбуці)
```
cd app
npm install
npm run dev           # http://localhost:5173, тестові дані: http://localhost:5173/?x#demo:v22.xlsm (файли в app/localtest/)
npm run build         # застосунок у app/dist
npm run build:sender  # сторінка для ПК у app/dist-sender
```
Кожен push у `main` автоматично публікує застосунок на GitHub Pages (`.github/workflows/pages.yml`).

Файли `.xlsm`, `.BAP`, маніфести, CSV та папки `testdata/`, `app/localtest/` не потрапляють у git, бо в них дані вантажу.
